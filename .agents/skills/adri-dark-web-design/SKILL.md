# Adri 다크 웹 디자인

다음 행동이 자연스럽게 보이는 명확한 위계를 통해 차분하고 자신감 있는 다크 인터페이스를 만든다. 레퍼런스 사이트의 명료함과 전환 흐름은 참고하되, 구성·문구·이미지·고유한 시각 표현은 복제하지 않는다.

## 제품에서 출발하기

1. 시각 방향을 제안하기 전에 저장소를 살펴본다. 기존 프레임워크, 컴포넌트 관례, 토큰, 에셋 파이프라인을 재사용한다.
2. 구체적인 주제, 핵심 사용자, 페이지가 수행할 한 가지 역할을 정한다. 브리프에 빠진 내용은 합리적으로 가정하고 그 가정을 밝힌다.
3. 디자인을 계획하거나 평가하기 전에 [디자인 언어 참고 문서](references/design-language.md)를 읽는다.
4. 사용자가 명시한 브랜드, 팔레트, 타이포그래피, 레이아웃, 접근성 요구를 이 스킬의 기본값보다 우선한다.

## 구현 전에 계획하기

다음 다섯 가지 결정을 포함한 간결한 디자인 계획을 작성한다.

- **색상:** 의미 기반 토큰의 이름과 역할을 정한다. 제품에 기존 팔레트가 없을 때만 다크 라벤더 기본값에서 시작한다.
- **타입:** 절제된 디스플레이 서체, 읽기 쉬운 본문 서체, 라벨이나 데이터용 유틸리티 스타일을 정한다. 가능하면 프로젝트의 기존 글꼴을 재사용한다.
- **레이아웃:** 그리드, 콘텐츠 리듬, 히어로의 핵심 주장, 반응형 재배치를 몇 문장이나 작은 ASCII 와이어프레임으로 설명한다.
- **시그니처:** 주제에 어울리는 기억할 만한 시각적 장치 하나를 고른다. 나머지 인터페이스는 이를 뒷받침하도록 차분하게 유지한다.
- **모션:** 하나의 조율된 모션 아이디어를 선택하거나 정적인 표현을 의도적으로 선택한다. 장식용 애니메이션을 페이지 곳곳에 흩뿌리지 않는다.

코드를 작성하기 전에 계획을 한 번 비평한다. 수정 없이 무관한 스타트업, 포트폴리오, 대시보드에도 적용될 수 있는 선택은 바꾼다. 디자인은 재사용 템플릿이 아니라 해당 주제에서 도출된 것처럼 보여야 한다.

## 저장소의 기존 기술로 구현하기

- 사용자가 변경을 요청하지 않은 정상 동작과 기존 콘텐츠는 보존한다.
- 시맨틱 HTML과 재사용 가능한 디자인 토큰을 사용한다. 컴포넌트 경계는 장식용 상자가 아니라 실제 콘텐츠와 동작에 맞춘다.
- 구체적이고 유용한 인터페이스 문구를 작성한다. 명확한 표시 없이 흔한 스타트업 문구, 꾸며낸 지표, 임시 후기를 사용하지 않는다.
- 레퍼런스의 흐름을 페이지의 실제 전환 목표에 맞게 조정한다. 실제 콘텐츠가 없는 섹션은 억지로 채우지 말고 생략한다.
- 이미지는 의미 있는 근거나 분위기로 사용한다. Adri의 에셋을 재사용하거나 레이아웃을 픽셀 단위로 복제하지 않는다.
- CSS 선택자 우선순위를 예측 가능하게 유지하고, 컴포넌트 스타일을 조용히 덮어쓰는 광범위한 선택자를 피한다.

## 기본 품질 충족하기

- 모바일, 태블릿, 데스크톱 너비에서 가로 넘침이나 읽기 어려운 글자 없이 동작하게 한다.
- 눈에 잘 보이는 키보드 포커스, 시맨틱 랜드마크, 유용한 대체 텍스트, 컨트롤의 접근 가능한 이름을 제공한다.
- 핵심 텍스트와 컨트롤은 WCAG AA 명암비를 충족하고, 상태를 색상만으로 전달하지 않는다.
- `prefers-reduced-motion`을 존중하고 모션이 꺼져도 인터페이스를 사용할 수 있게 한다.
- 제품에 필요한 경우 목적이 분명한 호버, 활성, 로딩, 빈 상태, 오류 상태를 포함한다.

## 결과 검토하기

미리보기나 스크린샷 도구를 사용할 수 있으면 넓은 화면과 좁은 화면을 각각 하나 이상 확인한다. 위계, 줄바꿈, 이미지 크롭, 명암비, 포커스 표시, 여백 리듬을 점검한다. 검토 후 불필요한 시각 효과를 하나 이상 덜어낸다.

최종 응답에서는 시각 방향을 요약하고, 주요 변경 파일과 수행한 반응형·접근성 검사를 알린다. 모든 스타일 결정을 장황하게 나열하지 않는다.
